# 图文邮件、定时发送与邮件任务

[返回简介](../README.md) · [English](OUTGOING-AUTOMATION.en.md)

## 编辑和回复

1. 从「收发邮件」打开邮件，选择回复、回复全部或转发，保存到草稿。
2. 草稿可用纯文本，或在正文格式中选择 HTML。可同时填写纯文本替代正文；留空时从 HTML 生成。
3. 保存后预览实际发件人、全部 To/Cc、正文和附件，再勾选核对并确认。保存或预览均不会发送。

HTML 支持段落、链接、列表、表格与常用内联文字/边框/间距样式。脚本、事件、表单、危险链接、远程图片和 CSS URL 不会发出；预览通过惰性结构化节点显示，不执行 HTML。发出的邮件为纯文本 + HTML 的 MIME 替代正文。回复保留原邮件线程关联；转发保留相关引用，不强制伪装成原线程回复。

「邮箱账号」的全局设置可选引用语言：跟随界面、中文、英语、法语；可填写 IANA 时区，例如 `Asia/Shanghai`。工具可传 `locale` / `timeZone` 覆盖。服务端无法获知浏览器语言时默认英语，账号显式设置优先。日期按可读本地格式显示，原邮件没有日期时显示相应语言的占位。

工具 `email_send`、`email_reply`、`email_draft` 接受可选 `html`；可只填 HTML。`email_draft` 的 `reply: {uid, folder, mode}` 创建带关联的回复/转发草稿。发信仍受禁止收件人规则和宿主权限约束。

「允许可信回复免审」默认关闭。开启后，只有该账号保存了 `skipApproval` 且所有**实际** To/Cc 都可信时，模型回复、回复全部或转发才跳过插件确认。禁止规则和 DSH 权限仍然有效；手动预览草稿不依赖此开关。收件人取自已读取并锁定的原邮件，确认后不会再次按变化的原邮件改写信封。

## 确认后定时发送

1. 编辑并保存草稿，在「定时发送」填写本机日期与时间。
2. 预览中核对完整时间、时区、收件人和附件，勾选核对并确认定时发送。
3. 任务变为「已定时」后只读；要修改，先取消定时并返回草稿。

模型可用 `email_schedule` 的 schedule/list/cancel 操作。保存 `email_draft.sendAt` 仅提出时间；正式排程总要单独确认，不受可信收件人免审开关影响。工具时间必须是含时区的 ISO 时间；最早 30 秒后、最晚一年内。

定时邮件与审核过的附件副本持久保存。到期前复核账号、规则和附件内容；改动时返回草稿要求重新确认。DSH 需要保持运行。关闭 DSH 时错过时间，重启后不会补发；进程暂停超过五分钟也需重新确认。发送结果不确定时不重试，请先核对发件箱；SMTP 回执只表示服务器接受，不保证最终投递。取消不能撤回已进入 SMTP 的邮件。

## Gmail 授权

已有 Gmail 应用密码账号保持原样。需要 OAuth 时，在 Gmail 账号卡片将认证方式改成 OAuth2：

1. 在 Google Cloud 配置自己的 OAuth 同意屏、Gmail 邮件授权范围与测试用户；创建 **Desktop app / 桌面应用** 客户端。
2. 填写 Google 客户端 ID；注册信息提供客户端密钥时也填写。插件不内置或借用他人的 Google 应用身份。
3. 点击「使用 Google 登录」，打开授权链接，选择**与卡片相同的邮箱**并授权，返回 DSH 等待状态更新，再测试连接。

采用授权码 + PKCE、随机 state 与本机随机端口回调；核对 Google 返回的已验证邮箱。授权范围为 `https://mail.google.com/`，附带 openid/email 用于账号核对。刷新令牌与邮箱密码分开保存；Windows 使用当前用户 DPAPI，令牌不进入账号 YAML 或界面。更换应用/邮箱需重新登录；注销、取消和配置变化不会让旧流程恢复已删除的登录。

Google 测试应用的刷新令牌寿命、组织策略与发布验证要求由 Google 决定。应用密码并非对所有账号一律停用：是否可生成取决于两步验证和组织/账号策略。此版本完成协议模拟与本机回调验收；未使用真实 Google 应用和邮箱完成端到端授权。

官方资料：[桌面 OAuth 与 PKCE](https://developers.google.com/identity/protocols/oauth2/native-app)、[Gmail IMAP/SMTP OAuth](https://developers.google.com/workspace/gmail/imap/imap-smtp)、[应用密码适用条件](https://support.google.com/mail/answer/185833)。

## 腾讯企业邮箱

选择 `exmail`：IMAP `imap.exmail.qq.com:993`、SMTP `smtp.exmail.qq.com:465`，均使用 TLS；POP3 为 `pop.exmail.qq.com:995`。填写完整企业邮箱地址与服务商要求的密码/专用授权码。管理员的协议开关与账号策略仍适用。自建或不同地域服务器继续用自定义预设/显式端点覆盖。此版本验证配置解析和协议路径，未连接真实企业账号。

## 用邮件发起 DSH 任务

该功能**默认关闭**，不是所有收到的邮件都当成指令。

任务主题前缀默认 `dsh`，可在同页改成自己的短前缀；下文示例相应替换。自动回复会优先请模型生成安全 HTML 片段，再统一过滤排版并生成纯文本备选。

1. 在「邮件任务」选择接收账号与文件夹，填写允许的发件人；留空仅允许邮箱本人。
2. 配置工作区别名，例如 `work = E:/projects/my-project`，保存。目录必须已存在，邮件只允许选择这些别名。
3. 生成任务口令，复制并妥善保管：只显示一次，本地保存校验摘要。轮换口令会暂停功能并使旧口令失效。
4. 主动启用并保存。第一次检查只建立起点，之前已在邮箱中的任务不会执行。
5. 发件人和口令均匹配的新邮件才可触发。主题为 `dsh:work`；正文第一行 `DSH-Key: 你的任务口令`，随后填写任务。
6. DSH 创建普通原生会话、沿用默认预设和模型。权限/提问仍在 DSH 中处理；任务列表可打开原会话。
7. 要接续同一会话，主题改为 `dsh:work:会话ID`；该会话须空闲且属于同一允许工作区。

任务使用你的模型，可能产生用量。口令授权白名单发件人在指定工作区发起任务，请勿转发或放进公开邮件。插件在交给模型前移除口令与引用历史；不把任务正文写进任务账本，普通 DSH 会话仍会保存任务内容。

「自动回复最终结果」是另一个默认关闭的开关。启用后仅向已授权发件人回复安全 HTML + 纯文本结果，不添加 Cc、不引用含口令的原正文，并核对禁止收件人规则；保留原线程，正文提供可复制的后续主题（包含会话 ID）。SMTP 同时设置此主题；AgentMail 的回复接口由服务保留原主题，因此继续任务时请复制正文中的主题。发送不确定时不自动重试。未启用时只在 DSH 内查看结果。

高级规则先经过发件人和口令核对，支持 all/any 与 subject/body/from/to/cc 条件，操作 contains/equals/regex；命名正则分组可用 `${name}` 写入 workspace/session/prompt 模板，`${body}` 是去除口令和引用后的正文。最终工作区仍须匹配允许别名。正则在有时间与内存限制的独立 worker 中运行。

```json
[{"mode":"all","conditions":[{"field":"subject","op":"regex","value":"^Task (?<project>work)$"}],"workspace":"${project}","prompt":"${body}"}]
```

DSH 需保持运行；最多 200 条任务记录，界面可清理已结束记录。轮询最多检查最新 100 封，超出连续窗口会明确暂停并要求重新建立起点。相同邮件不重复执行。重启后进行中任务转为需查看，不自动重放；人工接手、配置改变、运行超 30 分钟、会话失败或无最终文本时停止自动回复，原会话可在 DSH 中继续。任务不是全天候无人值守服务。AgentMail 仍只有模拟账号验收，真实服务需用户另行配置。
