# 通讯录 SQLite + 拼音检索（未发布）

日期：2026-11-20 ｜ 环境：Windows、本仓库检出、离线 Node 22.20 跑测试，宿主桌面端自带 Node 24.21 跑插件。

## 本次改了什么

- 通讯录存储从 `data/dsh-email/contacts-v1.json` 换成 `data/dsh-email/contacts-v2.sqlite3`（`node:sqlite`，SQLite 3.50.4）。
- 写入时预计算检索串（汉字名、全拼音节、拼音首字母、邮箱本地部分/工号、部门拼音），写信时 To/Cc 支持 `张小` / `zxm` / `zhangxiaoming` / `100123` 检索同一联系人。
- 姓氏多音字按姓氏读音索引（`surname: 'head'`）；通讯录上限 5 万条、自动条目 5 千条。
- 新增依赖 `pinyin-pro@3.29.5`（纯 JS，无原生编译）。
- 预留 `sync_state` 表，保存后续目录同步（CardDAV / LDAP）的游标。

## 已验证

- **离线测试**：`node --test test/*.test.mjs` 620 项全部通过（含新增 3 项：服务端拼音/首字母/工号检索、检索串构成、写信弹窗按 keys 命中）。
- **运行环境**：插件宿主 Node 24.21.0 下 `node:sqlite` 与 FTS5 均可加载；桌面端主程序以 `ELECTRON_RUN_AS_NODE` 运行与自带 `node.exe` 两种方式各验证一次。
- **旧数据迁移（真实通讯录的副本，不碰现场目录）**：把实际 `contacts-v1.json`（18 条）复制到临时 home 后导入，18 行全部落库、检索串正确，中文、全拼、首字母、工号与英文名均命中预期联系人；重新打开不重复导入。原文件未改动。
- **损坏文件行为**：`contacts-v1.json` 内容非法时报 `contact-storage` 且保留原文件，不静默清空（测试覆盖）。

## 未验证 / 已知边界

- 需要重启宿主后才加载新的 `lib/`；浏览器需刷新一次才能拿到新的 client bundle。
- 浏览器端仍是「整本下发 + 本地匹配」，条目达到数万级时会是一次数 MB 的 payload；目录同步落地前需要改为服务端检索 + 分页。
- 集团通讯录的来源尚未接入：CardDAV 适配器未实现。服务器侧只做了只读探测（不改变任何数据），结论记录在本地：IMAP 协议本身没有通讯录接口，私有 HTTP API 的方法名未公开，CardDAV 已开启但当前保存的凭据登录失败，标准 LDAP 端口未开放。
