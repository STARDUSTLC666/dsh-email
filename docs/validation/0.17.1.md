# 0.17.1 发信策略与设置保存验收

日期：2026-10-18。对应 [Issue #19](https://github.com/STARDUSTLC666/dsh-email/issues/19)。

环境：Windows x64、Node 24.16.0、官方 npm `@deepseek-ai/dsh@0.2.1-rc.2`，独立 `DSH_HOME`。实际安装候选 tarball；两个账号的 SMTP 均指向 `127.0.0.1` 测试服务，地址使用 `.invalid`。

## 改动

- 账号页已有全局 `sendApproval` 开关；关闭后新增中英文影响范围提示，只读设置不能编辑该开关。可信名单仍是按账号、所有 To/Cc 均匹配才跳过 `email_send` 确认。
- 修复新版宿主直接保存空服务商后，自定义 IMAP/SMTP 账号报 `provider "" 未知`。空选择与旧设置投影、YAML 序列化一致地按未设置处理，未知的非空服务商仍报错。

## 验证结果

| 检查 | 结果 |
| :-- | :-- |
| 空服务商回归 | 修复前新增测试失败；修复后单账号、账号映射、YAML、账号级空值均保留服务器与凭据 |
| 本地全套测试 | 349 项通过，0 失败、0 跳过 |
| 真实宿主允许分支 | 可信 To/Cc 实际提交到本机 SMTP；全局关闭确认后两个账号均可向未列入可信名单的地址提交 |
| 拒绝优先与宿主权限 | 被禁止的 Cc 覆盖可信规则；全局关闭确认时，禁止地址和真实 `tools.guard()` 拒绝仍阻止 SMTP 提交 |
| 实际页面保存后发送 | 浏览器切换开关并自动保存后，两张自定义账号卡片仍可解析，后续工具发信获得本机 SMTP 回执 |
| 页面与持久化 | 中文提示可见；重载保留开关与提示；切换英文正常；重新开启后提示消失并保存 |
| 页面布局与可访问性 | 提示由复选框的 `aria-describedby` 关联；检查时内容宽度与滚动宽度均为 605px，无控制台错误 |
| 草稿确认 | 在真实宿主中关闭全局确认后，草稿预览成功，未明确确认的发送仍返回 400 |

## 未验证范围

本轮没有运行真实模型回合中的逐次审批弹框。宿主工具 API 在缺少活跃模型回合时不能完成该交互；默认确认、混合名单、其他账号、子域名与回复策略另有自动契约测试，不把非回合调用的失败算成交互审批验收。

未连接个人邮箱、真实 IMAP 或外部 SMTP，也未验证 OAuth 登录、实际收件箱投递或原生 Desktop 窗口操作。
