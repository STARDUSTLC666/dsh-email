# 草稿与收件人规则

[返回简介](../README.md) · [English](DRAFTS.en.md)

## 先编辑，再发送

让助手使用 `email_draft` 准备邮件，或在「设置 → 邮件 → 草稿」新建。这个工具只写本地草稿，不连接 SMTP 发信。参数为 `to`、`subject`、`text`，可选 `account`、`cc` 和本地附件路径数组 `attachments`。

1. 选择发件账号，编辑 To、Cc、主题和纯文本正文，然后保存。
2. 添加附件。网页文件选择器保存本插件的副本；工具提供的路径保留原文件引用。
3. 点「检查发送预览」，核对真实发件地址与显示名、展开后的全部 To/Cc、正文、附件名称和大小。可下载本次预览的附件检查。
4. 勾选已核对，再点「确认发送」。收件人规则即使全部匹配，草稿仍需这次手动确认。

预览的附件字节会固定下来，发送和下载使用同一份快照。预览有效期为 10 分钟；修改草稿、账号或保存规则后需重新检查。关闭设置可恢复当前页面会话中的未保存编辑，刷新或关闭整个应用前仍应保存。

## 回执和结果不明

回执列出 SMTP 服务器接受与拒绝的地址。服务器接受表示完成 SMTP 提交，不能保证邮件已进入收件箱。部分地址被拒绝时不会自动再次发送整封邮件。

超时、断开或应用中断后没有完整回执时，草稿显示「结果未确定」。先核对邮箱，避免重复投递；界面不提供对同一份已提交草稿直接重发的按钮。确有需要时，明确「复制为新草稿」，重新预览和确认。复制会保存独立的附件副本。

多个窗口修改同一草稿时使用版本检查。遇到冲突，当前输入会保留；可以继续编辑，或明确放弃当前编辑并重新打开已保存版本。

## 按账号的可信收件人

「收件人规则」页可为每个账号保存完整地址和域名，每行一项。地址匹配保留邮箱本地部分大小写；域名规范化为小写并支持 IDN。`example.com` 不包含 `sub.example.com`。显示名不会替代实际邮箱地址，地址组中的每个地址和全部 Cc 都参与检查。

默认不跳过确认。只有主动勾选允许跳过、规则已保存，且 `email_send` 的所有 To/Cc 都匹配时，才跳过插件自身确认。宿主的其他权限仍生效；`email_reply` 继续使用原审批流程。如果全局 `sendApproval` 已关闭，规则不会额外增加审批。

用「检查规则匹配（不发送）」试填 To/Cc。未保存的预览只用于检查当前编辑，不会改变实际发信规则。切换账号时可保存、放弃或保留未保存编辑。

配置文件中的字段为 `trustedRecipientsYaml`，按账号名组织：

```yaml
trustedRecipientsYaml: |
  work:
    skipApproval: true
    addresses:
      - colleague@example.com
    domains:
      - team.example.com
```

账号改名后旧规则不会自动作用于新账号。规则变化不会重建邮箱连接。

## 存储与范围

草稿保存于 `DSH_HOME/data/dsh-email/drafts-v1.json`，上传副本位于其下 `draft-uploads`。未指定 DSH_HOME 时使用 `~/.dsh`。同一 DSH_HOME 共用草稿，发件账号以当前 profile 配置为准，预览会显示实际身份。

最多保存 50 份草稿，正文最多 100 KiB，每份最多 10 个附件、合计 20 MiB；如果 `maxAttachmentBytes` 配置更小，使用较小上限。跨进程编辑和发送使用文件锁及原子写入；损坏文件会保留并报错，不会静默清空。

删除前说明范围，只删除本地草稿及插件上传副本，不删除引用原文件或邮箱邮件。本轮工作台用于新邮件；回复、回复全部和转发继续使用原 `email_reply`，不伪造原邮件线程信息。

工作台验收环境及未验证范围见 [0.15.0 验证记录](validation/0.15.0.md)。
